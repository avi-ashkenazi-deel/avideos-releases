# Time It — Work Log

A running log of what we've built and shipped for the **Time It** iPhone + Apple
Watch timer app.

## Where the project lives (important)

- **Repo:** `avi-ashkenazi-deel/avideos-releases`, branch
  `claude/multi-timer-watchos-app-irsjw0`.
- The app is in the **`time-it/` subfolder** of that repo — NOT a separate repo,
  and NOT at the home folder. (`time-it` is a subfolder because the GitHub
  integration couldn't create a standalone repo.)
- **On Avi's Mac:** `/Users/avi.ashkenazi/TimeItApp/time-it/` — so
  `project.yml` is at `/Users/avi.ashkenazi/TimeItApp/time-it/project.yml`.
  Run all `xcodegen` / `open` commands from inside that `time-it` directory.
- The Xcode project is **generated by XcodeGen** (`.xcodeproj` is git-ignored).
  The build/version numbers live in `project.yml`
  (`CURRENT_PROJECT_VERSION` / `MARKETING_VERSION`) — editing them in Xcode's UI
  gets wiped on the next `xcodegen generate`.

## How to ship (TestFlight, via Xcode on the Mac)

```sh
cd /Users/avi.ashkenazi/TimeItApp/time-it
git pull origin claude/multi-timer-watchos-app-irsjw0
# bump CURRENT_PROJECT_VERSION in project.yml above the last uploaded build
xcodegen generate
open TimeIt.xcodeproj
# destination: Any iOS Device (arm64) → Product ▸ Archive
# Organizer ▸ Distribute App ▸ App Store Connect ▸ Upload
```

App icons are already in both asset catalogs. Three bundle IDs:
`com.aviashkenazi.timeit` (iPhone), `.watchkitapp` (watch), `.widget` (Live
Activity). Full detail in `TESTFLIGHT.md`. Each upload needs a **higher build
number** than the last (App Store Connect already has earlier versions — this is
NOT the first upload).

## 2026-06-23 — Live Activity polish, keep-awake, cue preview

State at this point: all changes committed and pushed; latest commit `3f09ae7`.

- **Live Activity — color + interval time** (`e9730b8`): the Lock Screen card and
  Dynamic Island now lead with the *current interval's* countdown (matching the
  in-app running screen) with the total run time shown secondary, and the card /
  keyline are tinted with the timer's color. Plain single-interval timers keep the
  total as the hero. Interval window is anchored to wall-clock dates so the widget
  ticks on its own without per-second push updates.
  (`TimerActivityAttributes` gained interval fields with decode-safe defaults;
  `LiveActivityController` populates them + derives a Work/Rest/cue/"Interval i/N"
  label; `TimerLiveActivity` drives the hero off the interval range.)
- **Keep the iPhone awake during exercise** (`af867fa`): while the running-timer
  screen shows an active timer, the idle timer is disabled
  (`UIApplication.isIdleTimerDisabled`) so the display stays on mid-set; normal
  auto-sleep is restored when the timer ends or the screen goes away. Foreground
  only — background liveness is still the audio/workout keep-alive.
- **Cue preview timeline for non-sport timers** (`3f09ae7`): new
  `TimerPreset.feedbackTimeline()` builds a second-by-second, time-ordered list of
  everything one run will speak or vibrate — lead-in ("3,2,1… Let's go"), each
  interval/milestone cue, the final spoken countdown expanded N…1, and the finish.
  The editor renders it as a **"Cue preview"** section at the bottom, shown only
  when "Record as Apple Watch workout" is **off** (talks, cooking…). Each row shows
  the elapsed mark, time remaining, the cue, and 🔊/📳 icons; footer notes
  per-interval countdowns and repeats.
